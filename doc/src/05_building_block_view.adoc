==== Blackbox Static Content
*Zweck/Verantwortung*

Stellt die Build-Artefakte der Angular-SPA (HTML, CSS, JavaScript, Assets) per HTTP bereit. Der Baustein enthält keine Logik und keinen Zustand.

*Schnittstelle(n)*

* HTTP GET auf statische Dateien (Einstiegspunkt `index.html`)

==== Blackbox Angular-UI
*Zweck/Verantwortung*

Single-Page-Application, die den Live-Ticker im Webbrowser darstellt und
Benutzerinteraktionen behandelt. Ruft alle Daten über die REST-API des Backends ab.

*Schnittstelle(n)*

Die UI stellt selbst keine Schnittstelle bereit, sie nutzt folgende:

* *REST-API des NestJS-Backends* (JSON über HTTP), siehe <<Blackbox NestJs Backend>>
* *Browser-LocalStorage* zur lokalen Ablage von Authentifizierungsdaten
* *WebAuthn-Browser-API* (`navigator.credentials`) für die passwortlose Authentifizierung

*Verzeichnis/Dateiort*: `frontend/`

==== White Box Angular-UI
image::ComponentDiagramUI.png[]
Die Angular-UI ist nach Fachbereichen (Features) gegliedert: Game, Team und Login.
Jedes Feature enthält seine eigenen Seiten, Container-Komponenten und Services und ist
damit weitgehend unabhängig von den anderen.
Querschnittlichte Aspekte (Routing, Authentifizierung, App-Layout) liegen ausserhalb
der Features. Die Feature-Seiten werden per Lazy Loading erst beim Aufruf der
jeweiligen Route geladen.

*Struktur der Features*

Innerhalb eines Features wird die Verantwortung auf `Pages`, `Smart Containers` und
`Dumb Components` aufgeteilt. Eine Page entspricht einer vom Benutzer aufgerufenen URL
(Route) und bindet die passenden `Smart Containers` ein.

Ein `Smart Container` ist ein Orchestrator: Er besitzt die Datenbeschaffung und die
Logik einer View und delegiert die reine Darstellung an `Dumb Components`.
`Dumb Components` erhalten ihre Daten ausschliesslich über Inputs und melden
Benutzeraktionen über Outputs. Sie kennen weder Services noch das Backend.

`Smart Containers` greifen über `Services` auf das Backend zu. `API-Services` kapseln
die REST-Aufrufe, Domain-Services enthalten Logik, die nur im Client benötigt wird.

*Enthaltene Bausteine*

[cols="1,3,2"]
|===
|Name |Verantwortlichkeit |Verzeichnis (`frontend/src/app/`)

|App Shell
|Grundlayout mit Navigation, Side-Nav und Router-Outlet. Blendet Navigationseinträge abhängig vom Login-Status ein oder aus.
|`app.ts`, `components/`

|Router
|Ordnet Pfade den Pages zu (Lazy Loading) und wendet die Route Guards an.
|`config/app.routes.ts`, `config/paths.config.ts`

|Auth Service
|Hält das JWT und den Login-Status. Das Token wird im LocalStorage (`auth`) persistiert.
|`authentication/auth.service.ts`

|Auth Interceptor
|Ergänzt jeden ausgehenden HTTP-Request um den Header `Authorization: Bearer <JWT>`, sofern ein Token vorhanden ist.
|`authentication/auth.interceptor.ts`

|Route Guards
|`authGuard` leitet nicht angemeldete Benutzer auf `/login` um, `anonymousGuard` verhindert den Zugang zur Login-Seite für angemeldete Benutzer.
|`authentication/guards/`

|Game Pages
|Seiten für Spielübersicht, Spieldetail sowie das Erfassen von Spielen und Spielereignissen.
|`features/game/pages/`

|Game Smart Containers
|Home, Spielliste, Spieldetail, Spiel erfassen und Ereignis erfassen. Laden Spiele und Teams und lösen Erstellungsaktionen aus. Enthalten die Dumb Components des Features.
|`features/game/smart_containers/`, `features/game/dumb_components/`

|Game Service
|Clientseitige Spiellogik: Status (live, bevorstehend, beendet) und Torstand aus den Spielereignissen ableiten.
|`features/game/service/game.service.ts`

|Game API
|Zugriff auf die REST-Schnittstelle `/api/games`.
|`features/game/service/game.api.ts`

|Team Pages
|Seiten für Team-Übersicht und Team-Detail (nur für angemeldete Benutzer erreichbar).
|`features/team/pages/`

|Team Smart Containers
|Team-Liste mit Erfassen, Ändern und Löschen von Teams. Enthalten die Dumb Components des Features.
|`features/team/smart_containers/`, `features/team/dumb_components/`

|Team API
|Zugriff auf die REST-Schnittstelle `/api/teams`. Wird auch vom Game-Feature genutzt, um beim Erfassen eines Spiels die Teams zu laden.
|`core/services/team.api.ts`

|Login Container
|Registrierung und Anmeldung mit Login-Formular.
|`features/user/smart_containers/`, `features/user/dumb_components/`

|WebAuthn Service
|Führt den WebAuthn-Ablauf (Optionen holen, Browser-Dialog, Ergebnis verifizieren) mit `@simplewebauthn/browser` durch und übergibt das erhaltene JWT an den Auth Service.
|`features/user/services/`
|===
